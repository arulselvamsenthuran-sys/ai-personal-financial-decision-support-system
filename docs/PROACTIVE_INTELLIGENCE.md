# Phase 18 — Proactive Financial Intelligence Documentation

## Overview

The **Proactive Intelligence Engine** automatically identifies meaningful financial changes, baseline trends, risks, and opportunities from a user's verified transaction data **without requiring the user to prompt or ask a question first**.

---

## Core Invariants

1. **Source of Truth**: All proactive insights are generated by a **deterministic calculation engine**. The LLM is NEVER the financial calculation engine.
2. **User Isolation**: All queries are strictly scoped by the authenticated user's session (`user_id`). IDOR access across users is strictly prevented.
3. **Data Sufficiency Enforcement**: If transaction history is sparse (< 5 total transactions or < 2 baseline transactions), proactive insight generation is suppressed to prevent false alarms.
4. **Currency Isolation**: Multi-currency transactions are evaluated independently per currency and never cross-aggregated.
5. **Deduplication**: Insight IDs are deterministically derived from metric signatures, preventing duplicate insight notifications across repeated API calls.
6. **Safe AI Explanation**: LLM explanations receive verified evidence wrapped in XML trust boundaries (`<verified_proactive_insight>`). If the LLM provider fails or is disabled, the deterministic insight and evidence remain available to the user.

---

## Centralized Thresholds

All evaluation thresholds are centralized in `app/services/proactive_intelligence.py`:

| Threshold Constant | Value | Description |
|-------------------|-------|-------------|
| `MIN_TRANSACTIONS_REQUIRED` | `5` | Minimum total user transactions required for baseline evaluation |
| `SPENDING_CHANGE_THRESHOLD_PCT` | `15.0%` | Minimum spending increase/decrease vs 3-month baseline to trigger insight |
| `SAVINGS_RATE_CHANGE_THRESHOLD_PCT` | `5.0%` | Minimum savings rate change (percentage points) to trigger insight |
| `INCOME_CHANGE_THRESHOLD_PCT` | `15.0%` | Minimum income decrease/increase vs baseline to trigger insight |
| `RECURRING_INCREASE_THRESHOLD_PCT` | `10.0%` | Minimum increase in recurring merchant charge vs historical average |

---

## Insight Types & Severity Rules

- `SPENDING_INCREASE`: Recent spending exceeds historical 3-month baseline. (Severity: `LOW` / `MEDIUM` / `HIGH` depending on variance magnitude).
- `SPENDING_DECREASE`: Recent spending decreased significantly vs baseline. (Severity: `INFO`).
- `SAVINGS_RATE_DECLINE`: Savings rate dropped compared to historical average. (Severity: `MEDIUM` / `HIGH`).
- `SAVINGS_RATE_IMPROVEMENT`: Savings rate increased compared to historical average. (Severity: `INFO`).
- `CASH_FLOW_DETERIORATION`: Net cash flow turned negative over recent 30 days. (Severity: `HIGH`).
- `CASH_FLOW_IMPROVEMENT`: Net cash flow improved over historical average. (Severity: `INFO`).
- `INCOME_CHANGE`: Income decreased significantly vs 3-month baseline. (Severity: `MEDIUM` / `HIGH`).
- `RECURRING_EXPENSE_INCREASE`: Detected recurring merchant cost increased. (Severity: `LOW`).

## API Endpoints

### 1. `GET /api/financial/proactive-insights`
- **Auth**: Required (Session Cookie)
- **Response**: `ProactiveInsightsResponse` containing `data_sufficient`, `currencies_evaluated`, and list of `ProactiveInsight` objects.

### 2. `POST /api/financial/proactive-insights/explain`
- **Auth**: Required (Session Cookie)
- **Body**: `{"insight_id": "...", "question": "..."}`
- **Security**: Rate limited, prompt injection scanned, XML data wrapped.
- **Response**: `ProactiveExplainResponse` with natural language explanation and standard disclaimer.
